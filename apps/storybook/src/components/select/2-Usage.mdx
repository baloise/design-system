## Declaring Options

Options can be declared as HTML markup with slotted `ds-select-option` (and `ds-select-optgroup`) elements, or set
programmatically via the `options` / `optionGroups` prop.

- Use **slots** when options come from server-rendered markup (backend-only apps, CMS templates), when migrating
  existing `<select>`/`<ds-select-option>` markup, or when the list is static and known at author time.
- Use the **`options` / `optionGroups` prop** when options come from application state or an API response — it
  keeps the list data-driven and is the natural fit for React, Angular, and other component-based frameworks.

<HTMLFramework>

```html
<ds-select id="select-country" label="Country" description="Select your country of residence"></ds-select>

<script>
  document.querySelector('#select-country').options = [
    { label: 'Switzerland', value: 'ch' },
    { label: 'Germany', value: 'de' },
    { label: 'Italy', value: 'it' },
  ]
</script>
```

</HTMLFramework>

<ReactFramework>

```tsx
import { DsSelect } from '@baloise/ds-react'

const countryOptions = [
  { label: 'Switzerland', value: 'ch' },
  { label: 'Germany', value: 'de' },
  { label: 'Italy', value: 'it' },
]

export function CountrySelect() {
  return <DsSelect
    label="Country"
    description="Select your country of residence"
    options={countryOptions} />
}
```

</ReactFramework>

<AngularFramework>

```html
<!-- app.component.html -->
<ds-select
  label="Country"
  description="Select your country of residence"
  [options]="countryOptions"></ds-select>
```

```ts
// app.component.ts
import { Component } from '@angular/core'
import { DsSelect } from '@baloise/ds-angular'

@Component({
  selector: 'app-country-select',
  imports: [DsSelect],
  templateUrl: './app.component.html',
})
export class AppComponent {
  countryOptions = [
    { label: 'Switzerland', value: 'ch' },
    { label: 'Germany', value: 'de' },
    { label: 'Italy', value: 'it' },
  ]
}
```

</AngularFramework>

## When to Use

- Present a list of mutually exclusive options in a form
- Conserve vertical space compared to radio buttons for longer option lists
- Let users filter a long list of options with `searchable`
- Allow selection of several values at once with `multiple`
- Organize related options under labeled groups with `optionGroups`

## When NOT to Use

- For 2–3 options — use radio buttons instead for better discoverability
- When all options should always be visible — use radio buttons or checkboxes
- For a single boolean choice — use a checkbox or toggle
- For free-text entry — use a regular input

## Do's and Don'ts

### Placeholder Text

Use `placeholder` to hint at the expected selection, but never as a replacement for the `label`.

<UsageExamples
  items={[
    {
      type: 'correct',
      title: 'Correct: Label with placeholder hint',
      content: <ds-select label="Country" placeholder="Select a country"></ds-select>,
      description: 'The label always identifies the field, even before a value is chosen',
    },
    {
      type: 'incorrect',
      title: 'Incorrect: Placeholder used as label',
      content: <ds-select label="" placeholder="Select a country"></ds-select>,
      description: 'Screen reader users lose context once a value is selected',
    },
  ]}
/>

### Searchable Long Lists

Enable `searchable` when the option list is long enough that scanning it is slower than typing.

<UsageExamples
  items={[
    {
      type: 'correct',
      title: 'Correct: Searchable for long lists',
      content: <ds-select label="Country" searchable></ds-select>,
      description: 'Users can quickly filter dozens of countries by typing',
    },
    {
      type: 'incorrect',
      title: 'Incorrect: Searchable for a handful of options',
      content: <ds-select label="Yes or no" searchable></ds-select>,
      description: 'Adds unnecessary interaction cost for a trivial choice',
    },
  ]}
/>
