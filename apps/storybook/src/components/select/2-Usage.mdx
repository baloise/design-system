## When to Use

- Present a list of mutually exclusive options in a form
- Conserve vertical space compared to radio buttons for longer option lists
- Let users filter a long list of options with `searchable`
- Allow selection of several values at once with `multiple`
- Organize related options under labeled groups with `optionGroups`

## When NOT to Use

- For 2–3 options — use radio buttons instead for better discoverability
- When all options should always be visible — use radio buttons or checkboxes
- For a single boolean choice — use a checkbox or toggle
- For free-text entry — use a regular input

## Do's and Don'ts

### Placeholder Text

Use `placeholder` to hint at the expected selection, but never as a replacement for the `label`.

<UsageExamples
  items={[
    {
      type: 'correct',
      title: 'Correct: Label with placeholder hint',
      content: <ds-select label="Country" placeholder="Select a country"></ds-select>,
      description: 'The label always identifies the field, even before a value is chosen',
    },
    {
      type: 'incorrect',
      title: 'Incorrect: Placeholder used as label',
      content: <ds-select label="" placeholder="Select a country"></ds-select>,
      description: 'Screen reader users lose context once a value is selected',
    },
  ]}
/>

### Searchable Long Lists

Enable `searchable` when the option list is long enough that scanning it is slower than typing.

<UsageExamples
  items={[
    {
      type: 'correct',
      title: 'Correct: Searchable for long lists',
      content: <ds-select label="Country" searchable></ds-select>,
      description: 'Users can quickly filter dozens of countries by typing',
    },
    {
      type: 'incorrect',
      title: 'Incorrect: Searchable for a handful of options',
      content: <ds-select label="Yes or no" searchable></ds-select>,
      description: 'Adds unnecessary interaction cost for a trivial choice',
    },
  ]}
/>
