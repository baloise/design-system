## Guidelines

<A11yGuidelines
  items={[
    {
      type: 'do',
      title: 'Always Provide a Label',
      content: (
        <p style={{ margin: '0.5rem 0 0 0' }}>
          Set a descriptive <code>label</code>. It is associated with the national-number field and included in the
          country trigger's accessible name, so both controls have context.
        </p>
      ),
    },
    {
      type: 'do',
      title: 'Explain Invalid State in Text',
      content: (
        <p style={{ margin: '0.5rem 0 0 0' }}>
          When <code>invalid</code> is set, provide <code>invalidText</code> (or the <code>invalid-text</code> slot) so
          assistive technology can announce why the value needs to change.
        </p>
      ),
    },
    {
      type: 'do',
      title: 'Keep Country Identity in Text, Not the Flag',
      content: (
        <p style={{ margin: '0.5rem 0 0 0' }}>
          Flags are decorative. The trigger already exposes the localized country name and calling code — do not add a
          redundant <code>alt</code> or <code>aria-label</code> on a custom flag.
        </p>
      ),
    },
    {
      type: 'dont',
      title: "Don't Omit the Label",
      content: (
        <p style={{ margin: '0.5rem 0 0 0' }}>
          Never leave <code>label</code> empty. Without it, screen reader users hear a calling code and a number field
          with no indication that they belong together as a phone number.
        </p>
      ),
    },
    {
      type: 'dont',
      title: "Don't Treat Formatting as Validation",
      content: (
        <p style={{ margin: '0.5rem 0 0 0' }}>
          Do not assume a formatted value is a reachable phone number. Pair <code>invalid</code> with application-side
          checks and an <code>invalidText</code> message rather than relying on grouping spaces.
        </p>
      ),
    },
  ]}
/>
