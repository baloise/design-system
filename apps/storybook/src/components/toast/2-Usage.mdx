## Present and dismiss a toast

`useToast()` returns `present` and `dismiss` functions. Pass notification content as data; toast content is not JSX.

<InfoQuote>
  Import `useToast` from `@baloise/ds-react`. The generated `DsToast` wrapper is deprecated.
</InfoQuote>

```tsx
import { DsButton, useToast } from '@baloise/ds-react'

export function ToastExample() {
  const [presentToast, dismissToast] = useToast()

  const showToast = () =>
    presentToast({
      heading: 'Saved',
      message: 'Your changes have been saved.',
      closable: true,
      duration: 5000,
      closeHandler: () => undefined,
      actionHandler: () => undefined,
    })

  return (
    <>
      <DsButton onDsClick={showToast}>Show toast</DsButton>
      <DsButton onDsClick={() => dismissToast()}>Dismiss toast</DsButton>
    </>
  )
}
```

</ReactFramework>

## Present and dismiss a toast

Use `dsToastController` from `@baloise/ds-core` (also available as `window.DesignSystem.toastController`) to create
and remove toasts. `create()` returns the toast's ID, which `remove()` needs to dismiss it early.

```html
<ds-button id="show-toast">Show toast</ds-button>
<ds-button id="dismiss-toast">Dismiss toast</ds-button>

<script type="module">
  import { dsToastController } from '@baloise/ds-core'

  let toastId

  document.querySelector('#show-toast').addEventListener('click', async () => {
    toastId = await dsToastController.create({
      heading: 'Saved',
      message: 'Your changes have been saved.',
      closable: true,
      duration: 5000,
      closeHandler: () => undefined,
      actionHandler: () => undefined,
    })
  })

  document.querySelector('#dismiss-toast').addEventListener('click', () => {
    if (toastId) dsToastController.remove(toastId)
  })
</script>
```

</HTMLFramework>

## When to Use

- Display brief, temporary notifications that auto-dismiss after a short duration
- Show confirmation messages for completed actions (e.g., "File saved successfully")
- Provide non-blocking feedback that doesn't require user action
- Inform users of background processes or updates that don't demand immediate attention

## When NOT to Use

- For notifications that need to remain visible for extended periods — use **Snackbar** instead
- For critical errors or warnings that require user interaction — use **Alert** in a modal dialog
- For large amounts of content or complex information — use a dedicated notification panel
- For form validation errors — use inline field-level feedback
