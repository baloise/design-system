<Lead>
  Test the Design System's web components inside your own Angular, React, or plain JS application with
  `@baloise/ds-playwright` — a thin wrapper around Playwright that waits for components to be ready and
  ships Page Objects for every component.
</Lead>

Design System components are asynchronous web components: they upgrade, render, and apply attribute
changes after a tick. A plain Playwright test can race that upgrade and interact with the element too
early. `@baloise/ds-playwright` re-exports Playwright's `test` and `expect` with this synchronization
built in, so tests behave the same whether the component was rendered by Angular, React, or plain HTML.

## Installation

```bash
npm install -D @baloise/ds-playwright
```

Then swap the import in your test files — everything else about writing a Playwright test stays the same:

```typescript
// Before
import { test, expect } from '@playwright/test'

// After
import { test, expect } from '@baloise/ds-playwright'
```

<InfoQuote>
  This package only helps with **end-to-end tests that run in a real browser**. Component behavior relies
  on Shadow DOM and custom element upgrades, which jsdom does not fully support — prefer Playwright over a
  jsdom-based runner (Jest, Vitest) when a test needs to interact with a Design System component.
</InfoQuote>

## Page Objects

Every component ships a **Page Object** — a class with typed locators and helper methods for interacting
with that component, so tests don't need to know its internal DOM structure. Wrap a `page.locator(...)`
pointing at the component's tag and call methods on it instead of querying the DOM directly.

```typescript
import { DsButton, expect, test } from '@baloise/ds-playwright'

test('submits the form', async ({ page }) => {
  await page.goto('/checkout')

  const submitButton = new DsButton(page.locator('ds-button[type="submit"]'))

  await submitButton.assertToBeVisible()
  await submitButton.click()
})
```

Each component's documentation page lists its Page Object's locators, actions, and assertions under its
**Testing** tab — check there for the exact class name and methods available for the component under test.

## Events

Spy on custom events a component fires and assert on them with the built-in matchers.

```typescript
import { DsButton, expect, test } from '@baloise/ds-playwright'

test('fires dsClick when clicked', async ({ page }) => {
  await page.goto('/checkout')

  const submitButton = new DsButton(page.locator('ds-button'))
  const spy = await page.spyOnEvent('dsClick')

  await submitButton.click()

  expect(spy).toHaveReceivedEventTimes(1)
})
```

<Markdown>
  {`
| Matcher                                     | Description                                                    |
| -------------------------------------------- | ---------------------------------------------------------------- |
| \`toHaveReceivedEvent()\`                    | Asserts the spied event was received.                          |
| \`toHaveReceivedEventDetail(eventDetail)\`   | Asserts the spied event was received with the expected detail. |
| \`toHaveReceivedEventTimes(count)\`          | Asserts how many times the spied event was received.           |
`}
</Markdown>

## Accessibility Testing

The `a11y` fixture runs axe-core (WCAG 2.2 AA rules) against a selector on the current page — useful for
catching accessibility regressions introduced by how your app composes or styles Design System components.

```typescript
import { test } from '@baloise/ds-playwright'

test('checkout form is accessible', async ({ page, a11y }) => {
  await page.goto('/checkout')
  await a11y('form')
})
```
