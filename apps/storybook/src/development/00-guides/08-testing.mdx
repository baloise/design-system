  The Helvetia Design System tests its components with Playwright, using a Page Object model to keep tests
  readable and maintainable.

Due to the asynchronous execution of these web components, it becomes essential to ensure proper
synchronization within tests. The `@baloise/ds-playwright` package takes care of this for you —
mounting components, waiting for the Design System to be ready, and exposing custom matchers.

## Test Types

| Test Type       | File Pattern         | Purpose                      | Assertions                          |
| ---------------- | --------------------- | ----------------------------- | ------------------------------------- |
| **Interaction** | `.component.play.ts` | User interactions, events    | Custom matchers for events          |
| **Visual**      | `.visual.play.ts`    | Visual regression            | Screenshot comparisons              |
| **A11y**        | `.a11y.play.ts`      | Accessibility compliance     | axe-core checks + manual assertions |

<InfoQuote>
  Run `pnpm play` to open the Playwright UI test explorer, or `pnpm play -- --grep="<test name>"` to run a single
  test from the command line.
</InfoQuote>

## Page Objects

A **Page Object** (PO) is a class that encapsulates the interaction logic for a component. Instead of
querying the DOM directly, tests call PO methods:

```typescript
import { expect } from '@playwright/test'
import { PageObject } from './page-object'
import { E2ELocator } from '../page/utils'

export class DsButton extends PageObject {
  constructor(el: E2ELocator) {
    super(el)
  }

  async click() {
    await this.el.click()
  }

  async assertToBeDisabled() {
    await expect(this.el).toHaveAttribute('disabled')
  }
}
```

Benefits:

- **Maintainability** — if the component's internal structure changes, only the PO needs updating
- **Readability** — tests read like plain English
- **Reusability** — every test for a component shares the same PO

Every component ships its PO in `packages/playwright/src/lib/components/<component>.po.ts`, exported from
`@baloise/ds-playwright`.

## Mounting Components

Mount components in the test body — never in `beforeEach` — to keep tests isolated and their intent clear.

```typescript
import { DsButton, expect, test } from '@baloise/ds-playwright'

test.describe('component', () => {
  test('should have a default slot', async ({ page }) => {
    await page.mount(`
      <ds-button>Click me</ds-button>
    `)

    const dsButton = new DsButton(page.locator('ds-button'))

    await dsButton.assertToBeVisible()
    await dsButton.assertToContainText('Click me')
  })
})
```

## Events

Spy on custom events fired by a component and assert on them with the built-in matchers.

```typescript
test('should fire dsClick event', async ({ page }) => {
  await page.mount(`
    <ds-button>Click me</ds-button>
  `)

  const dsButton = new DsButton(page.locator('ds-button'))
  const spy = await dsButton.el.spyOnEvent('dsClick')

  await dsButton.click()

  expect(spy).toHaveReceivedEventTimes(1)
})
```

<Markdown>
  {`
| Matcher                                     | Description                                                    |
| -------------------------------------------- | ---------------------------------------------------------------- |
| \`toHaveReceivedEvent()\`                    | Asserts the spied event was received.                          |
| \`toHaveReceivedEventDetail(eventDetail)\`   | Asserts the spied event was received with the expected detail. |
| \`toHaveReceivedEventTimes(count)\`          | Asserts how many times the spied event was received.           |
`}
</Markdown>

## Accessibility Testing

A11y tests verify WCAG 2.2 AA compliance using the `a11y` fixture, which runs axe-core checks against a mounted
component.

```typescript
import { test } from '@baloise/ds-playwright'

test('basic', async ({ page, a11y }) => {
  await page.mount(`<ds-button>Button</ds-button>`)
  await a11y('ds-button')
})
```

Components with no a11y tests cannot merge.

## Visual Regression Testing

Visual tests render a static HTML fixture and compare screenshots of each variant against an approved baseline.

```typescript
import { expectScreenshot, screenshot, test } from '@baloise/ds-playwright'

const TAG = 'button'
const VARIANTS = ['basic', 'disabled', 'loading']

const image = screenshot(TAG)

test.describe('style', () => {
  test.beforeEach('Setup', async ({ page }) => {
    await page.setupVisualTest(`/components/${TAG}/test/${TAG}.style.html`)
  })

  VARIANTS.forEach(variant => {
    test(variant, async ({ page }) => {
      const el = page.getByTestId(variant)
      await expectScreenshot(el, image(`style-${variant}`))
    })
  })
})
```

Snapshots live next to the test file in `<component>.visual.play.ts-snapshots/` and are tracked in git.
After an intentional visual change, re-baseline the snapshots with the `/update-screenshots` bot command on the
pull request — never commit updated snapshots generated locally.
