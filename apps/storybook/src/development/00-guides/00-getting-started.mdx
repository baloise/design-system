## Manual Installation

Continue here for the manual installation guide without schematics.

Let's install the latest Angular components. This package includes the Font, Token, Icon, and CSS-Utilities packages.

```bash
npm install @baloise/ds-Angular
```

### Import Styles

Add these to your global stylesheet (e.g. `styles.scss`). Only **Base** is required — add the others as you need them:

```css
// 1. Base — design tokens, CSS reset, and structural styles. Always required.
@use '@baloise/ds-css/scss/base';

// 2. Components — only needed if you use the CSS-only classes (e.g. `class="ds-button"`)
//    instead of the web components (`<ds-button>`), which load their styles automatically.
@import '@baloise/ds-css/css/components';

// 3. Utilities — spacing, layout, typography, color helpers, etc. Optional.
@import '@baloise/ds-css/css/utilities';
```

For SASS mixins (breakpoints, etc.) without any styles, import `@baloise/ds-css/scss/mixins` instead.

### Standalone

Use the `provideDesignSystem` provider within the `app.config.ts` file, where Angular providers are typically defined.

**app.config.ts**

```typescript
import { ApplicationConfig, importProvidersFrom } from '@angular/core'

import { provideDesignSystem } from '@baloise/ds-angular'

export const appConfig: ApplicationConfig = {
  providers: [provideDesignSystem()],
}
```

**app.component.ts**

Layout elements like `ds-root` and `ds-app-footer` are web components, so add the schema
`CUSTOM_ELEMENTS_SCHEMA` to your root angular component and import the bundle that registers them.

```typescript
import { CUSTOM_ELEMENTS_SCHEMA, Component } from '@angular/core'
import { CommonModule } from '@angular/common'
import { BalLayoutBundle } from '@baloise/ds-angular'

@Component({
  selector: 'app-root',
  standalone: true,
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  imports: [CommonModule, ...BalLayoutBundle],
})
export class AppComponent {}
```

**app.component.html**

Add the `ds-root` to your `app.component.html` root element. Elements like the button and heading
below are plain HTML styled with a CSS class — no import or registration needed.

```html
<ds-root class="has-sticky-footer">
  <header>
    <!-- Header content -->
  </header>
  <main class="ds-container">
    <!-- Your application content -->
    <h1 class="ds-heading">Hello World!</h1>
    <button class="ds-button">Button</button>
  </main>
  <ds-app-footer>
    <!-- Footer content -->
  </ds-app-footer>
</ds-root>
```

### Module Based

Import the `DesignSystemModule.forRoot()` into your angular root module.
To use the custom web components add the schema `CUSTOM_ELEMENTS_SCHEMA` to your root angular module.
For each angular sub module you need to import the `DesignSystemModule` to provide the components and the value accessors.

**app.module.ts**

```typescript
import { CUSTOM_ELEMENTS_SCHEMA, NgModule } from '@angular/core'
import { BrowserModule } from '@angular/platform-browser'
import { BalLayoutBundle, provideDesignSystem } from '@baloise/ds-angular'
import { AppComponent } from './app.component'

@NgModule({
  declarations: [AppComponent],
  imports: [
    BrowserModule,
    // Provide all components and value accessors to the app module.
    provideDesignSystem(),
    ...BalLayoutBundle,
  ],
  providers: [],
  bootstrap: [AppComponent],
  // To enable the usage of Web Components inside the Angular templates.
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
})
export class AppModule {}
```

**app.component.html**

Add the `ds-root` to your `app.component.html` root element.

<Code
  language="html"
  noPreview
  code={`
<ds-root class="has-sticky-footer">
  <header>
    <!-- Header content -->
  </header>
  <main class="ds-container">
    <!-- Your application content -->
    <h1 class="ds-heading">Hello World!</h1>
    <button class="ds-button">Button</button>
  </main>
  <ds-app-footer>
    <!-- Footer content -->
  </ds-app-footer>
</ds-root>
`}
/>

## Installation

No build tool, no framework — just an `index.html` file. This is the recommended setup for
static sites, server-rendered pages, or any HTML5 app you keep under version control with npm.

```bash
npm add -E @baloise/ds-core @baloise/ds-css
// or
pnpm add -E @baloise/ds-core @baloise/ds-css
```

## Usage

Create an `index.html` file in your project root and add the following:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta http-equiv="X-UA-Compatible" content="IE=edge" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Helvetia Design System</title>

    <!-- Configure the Design System before it boots -->
    <meta
      name="design-system-config"
      data-brand="helvetia"
      data-region="CH"
      data-language="de"
      data-allowed-languages="de,fr,it,en"
    />

    <!-- Required: design tokens, CSS reset, and structural styles -->
    <link rel="stylesheet" href="node_modules/@baloise/ds-css/css/base.css" />
    <!-- Optional: only needed if you use the CSS-only classes (e.g. class="ds-button") instead of the web components (<ds-button>) -->
    <link rel="stylesheet" href="node_modules/@baloise/ds-css/css/components.css" />
    <!-- Optional: only needed if you use utility classes (spacing, layout, typography, color helpers, etc.) -->
    <link rel="stylesheet" href="node_modules/@baloise/ds-css/css/utilities.css" />

    <!-- Register the web components used in markup -->
    <script
      type="module"
      src="node_modules/@baloise/ds-core/dist/design-system/design-system.esm.js"
    ></script>
    <script nomodule src="node_modules/@baloise/ds-core/dist/design-system/design-system.js"></script>

  </head>

  <body>
    <ds-root>
      <main class="ds-container mt-base">
        <h1 class="ds-heading">Hello World</h1>
        <button class="ds-button">Button</button>
      </main>
    </ds-root>
  </body>
</html>
```

Here's a complete, working page — the language/region `<meta>` tag, stylesheet, and scripts all
live in `<head>`; `ds-root` wraps the page content in `<body>`.

<br />

**What each part does**

- **`<meta name="design-system-config">`** — sets brand, region, and language before the app
  boots. Optional, but recommended so there's no flash of default config. See "Configure Language
  & Region" further below.
- **The three stylesheets** — `base.css` (design tokens, CSS reset, structural styles) is the
  only one you really need. `components.css` adds the CSS-only classes (`.ds-button`,
  `.ds-heading`, ...) used below. `utilities.css` (spacing, layout, typography, color helpers) is
  entirely optional — drop it if you don't use utility classes.
- **`<script type="module">` / `<script nomodule>`** — registers the web components (`<ds-root>`,
  `<ds-stage>`, etc.) used in markup. The `nomodule` variant is a fallback for browsers without
  ES module support.
- **`<ds-root>`** — the root layout web component; wrap your page content in it.
- **`<h1 class="ds-heading">` / `<button class="ds-button">`** — plain HTML styled with a CSS
  class. No script needed for these — only elements that need JS behavior (like `<ds-root>`) are
  web components.

### CDN

Prototyping or don't want to install anything? Load everything straight from
[jsDelivr](https://www.jsdelivr.com/), a CDN, by adding these to `<head></head>`:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@baloise/ds-css/css/base.css" />
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@baloise/ds-css/css/components.css" />
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@baloise/ds-css/css/utilities.css" />
<script
  type="module"
  src="https://cdn.jsdelivr.net/npm/@baloise/ds-core/dist/design-system/design-system.esm.js"
></script>
<script
  nomodule
  src="https://cdn.jsdelivr.net/npm/@baloise/ds-core/dist/design-system/design-system.js"
></script>
```

Same as before, only `base.css` is really required — drop `utilities.css` if you don't use utility
classes. The rest of the page (the `<meta name="design-system-config">` tag, `<ds-root>`, etc.) works
exactly like the "Plain HTML" example above — only where the CSS/JS come from changes.

`https://cdn.jsdelivr.net/npm/@baloise/ds-css@16/css/base.css`

## Installation

If you do not have a React app yet, create one with [Vite](https://vite.dev/guide/) (recommended for SPAs) or [Next.js](https://nextjs.org/docs/app/getting-started).

<InfoQuote>
  **Recommendations**

  - Use **TypeScript**. `@baloise/ds-react` ships its own types; no extra `@types` package or `tsconfig` flags are
    needed.
  - Use **SCSS** as stylesheet format to access breakpoint mixins and more. A pre-built CSS bundle is also available.
  - `react` and `react-dom` **18** or **19** are required as peer dependencies.
</InfoQuote>

Install the React bindings and the global styles. Both packages are required.

```bash
npm add -E @baloise/ds-react @baloise/ds-css
// or
pnpm add -E @baloise/ds-react @baloise/ds-css
```

## Usage

Component styles are automatically loaded lazily in the browser. Global CSS (fonts, resets, utilities) needs to be imported into the application.

Import the full stylesheet once, typically in `src/main.tsx`:

```typescript
import '@baloise/ds-css/css'
```

For a smaller payload, import the layers separately. Keep this order so tokens and resets are available before component and utility styles:

```typescript
// Required: design tokens, CSS reset, and structural styles
import '@baloise/ds-css/css/base'
// Optional: only needed if you use the CSS-only classes (e.g. class="ds-button") instead of the web components (<ds-button>)
import '@baloise/ds-css/css/components'
// Optional: only needed if you use utility classes (spacing, layout, typography, color helpers, etc.)
import '@baloise/ds-css/css/utilities'
```

### bootstrapDesignSystem

`bootstrapDesignSystem` initializes the Design System for a React app. Call it **once** at **module scope** in the app entry — `src/main.tsx` (Vite) or a client entry imported from a Next.js root layout — **before** `createRoot(...).render(...)`. It is not a React hook; do not call it inside a component function.

It applies optional region, language, and brand defaults. If you omit the call, components still work with the default config. Region and language can also be changed at runtime. See **Development/Internationalization**.

**main.tsx**

```tsx
import { bootstrapDesignSystem } from '@baloise/ds-react'
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'

import App from './App'

import '@baloise/ds-css/css'

bootstrapDesignSystem({
  defaults: {
    region: 'CH',
    language: 'de',
    allowedLanguages: ['de', 'fr', 'it', 'en'],
  },
})

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

### App root

Wrap the application in `DsRoot` and import the components you use.

**App.tsx**

```tsx
import { DsRoot, DsAppFooter, DsButton, DsHeading } from '@baloise/ds-react'

function App() {
  return (
    <DsRoot className="has-sticky-footer">
      <header>
        {/* Header content */}
      </header>
      <main className="ds-container">
        {/* Your application content */}
        <DsHeading>
          Hello World!
        </DsHeading>
        <DsButton>
          Button
        </DsButton>
      </main>
      <DsAppFooter>
        {/* Footer content */}
      </DsAppFooter>
    </DsRoot>
  )
}

export default App
```

## Frameworks

### Vite

Vite is the recommended setup for a client-side React SPA. Scaffold a TypeScript app, then install the Design System as described above. The app entry is `src/main.tsx`.

```bash
npm create vite@latest my-app -- --template react-ts
```

### Next.js

`@baloise/ds-react` is client-only today. Import Design System components from files marked `'use client'`. Call `bootstrapDesignSystem()` at module scope in a client entry file (imported from the root layout), not inside a component function.

### TypeScript

`@baloise/ds-react` publishes TypeScript declarations (`types` in `package.json` points at `dist/index.d.ts`). After installing the package, component props, events, and the `bootstrapDesignSystem` config are typed — no extra `@types/*` package or `tsconfig.json` changes are required.

Event handlers use the `onDs*` prefix (for example `onDsClick`) and receive the custom event, not a React synthetic event.
