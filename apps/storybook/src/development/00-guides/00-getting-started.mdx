## Installation

If you do not have an Angular app yet, create one with [Angular CLI](https://angular.io/guide/setup-local).

<InfoQuote>
  **Recommendations**

  - Use **SCSS** as stylesheet format to access breakpoint mixins and more. A pre-built CSS bundle is also available.
  - Angular **17+** with standalone components is required — the Design System ships no `NgModule`.
</InfoQuote>

Install the Angular bindings and the global styles. All three packages are required.

```bash
npm add -E @baloise/ds-angular @baloise/ds-styles @baloise/ds-tokens
// or
pnpm add -E @baloise/ds-angular @baloise/ds-styles @baloise/ds-tokens
```

## Usage

### Import Styles

Add these to your global stylesheet (e.g. `styles.scss`). Only **Tokens** and
**Foundation + Components** are required — add Utilities as you need it:

```css
// 1. Tokens — every --ds-* CSS custom property. Always required; load before Foundation + Components.
@import '@baloise/ds-tokens/css/base';

// 2. Foundation + Components — CSS reset, structural styles, and CSS-only component classes
//    (e.g. class="ds-button"). Ship together as one pre-built bundle. Always required.
@import '@baloise/ds-styles/css/design-system';

// 3. Utilities — spacing, layout, typography, color helpers, etc. Optional.
@import '@baloise/ds-styles/css/utilities';
```

For SASS mixins (breakpoints, etc.) without any styles, import `@baloise/ds-styles/scss/mixins` instead.

### provideDesignSystem

Angular apps are standalone by default. Add `provideDesignSystem()` to the providers in `app.config.ts` — it
initializes the system once and every nested component picks up brand, region, language, and animation settings.

Pass the default config via `defaults`. If you omit it, components still work with the default config. Region and
language can also be changed at runtime with `updateDsRegion` / `updateDsLanguage`. See **Development/Configuration**.

**app.config.ts**

```typescript
import { ApplicationConfig } from '@angular/core'
import { provideDesignSystem } from '@baloise/ds-angular'

export const appConfig: ApplicationConfig = {
  providers: [
    provideDesignSystem({
      defaults: {
        region: 'CH',
        language: 'de',
        allowedLanguages: ['de', 'fr', 'it', 'en'],
      },
    }),
  ],
}
```

**main.ts**

```typescript
import { bootstrapApplication } from '@angular/platform-browser'

import { App } from './app/app'
import { appConfig } from './app/app.config'

bootstrapApplication(App, appConfig).catch(err => console.error(err))
```

**app.ts**

Every component — including layout elements like `DsRoot` and `DsAppFooter` — ships as a real, standalone Angular
component generated from the underlying web component. Import what you need directly; no `CUSTOM_ELEMENTS_SCHEMA` is
required.

```typescript
import { Component } from '@angular/core'
import { DsAppFooter, DsButton, DsRoot } from '@baloise/ds-angular'

@Component({
  selector: 'app-root',
  imports: [DsRoot, DsAppFooter, DsButton],
  templateUrl: './app.html',
})
export class App {}
```

**app.html**

Add `ds-root` to your root template. Elements like the heading below are plain HTML styled with a CSS class — no
import or registration needed.

```html
<ds-root class="has-sticky-footer">
  <header>
    <!-- Header content -->
  </header>
  <main class="ds-container">
    <!-- Your application content -->
    <h1 class="ds-heading">Hello World!</h1>
    <ds-button>Button</ds-button>
  </main>
  <ds-app-footer>
    <!-- Footer content -->
  </ds-app-footer>
</ds-root>
```

## Installation

No build tool, no framework — just an `index.html` file. This is the recommended setup for
static sites, server-rendered pages, or any HTML5 app you keep under version control with npm.

```bash
npm add -E @baloise/ds-core @baloise/ds-styles @baloise/ds-tokens
// or
pnpm add -E @baloise/ds-core @baloise/ds-styles @baloise/ds-tokens
```

## Usage

Create an `index.html` file in your project root and add the following:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta http-equiv="X-UA-Compatible" content="IE=edge" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Helvetia Design System</title>

    <!-- Configure the Design System before it boots -->
    <meta
      name="design-system-config"
      data-brand="helvetia"
      data-region="CH"
      data-language="de"
      data-allowed-languages="de,fr,it,en"
    />

    <!-- Required: design tokens (--ds-* CSS custom properties). Load before ds-styles -->
    <link rel="stylesheet" href="node_modules/@baloise/ds-tokens/css/base" />
    <!-- Required: CSS reset, structural styles, and CSS-only component classes (e.g. class="ds-button") -->
    <link rel="stylesheet" href="node_modules/@baloise/ds-styles/css/design-system" />
    <!-- Optional: only needed if you use utility classes (spacing, layout, typography, color helpers, etc. — e.g. class="mt-base" below) -->
    <link rel="stylesheet" href="node_modules/@baloise/ds-styles/css/utilities" />

    <!-- Register the web components used in markup -->
    <script
      type="module"
      src="node_modules/@baloise/ds-core/dist/design-system/design-system.esm.js"
    ></script>
    <script nomodule src="node_modules/@baloise/ds-core/dist/design-system/design-system.js"></script>

  </head>

  <body>
    <ds-root>
      <main class="ds-container mt-base">
        <h1 class="ds-heading">Hello World</h1>
        <button class="ds-button">Button</button>
      </main>
    </ds-root>
  </body>
</html>
```

Here's a complete, working page — the language/region `<meta>` tag, stylesheet, and scripts all
live in `<head>`; `ds-root` wraps the page content in `<body>`.

<br />

**What each part does**

- **`<meta name="design-system-config">`** — sets brand, region, and language before the app
  boots. Optional, but recommended so there's no flash of default config. See "Configure Language
  & Region" further below.
- **The three stylesheets** — `base.tokens.css` (from `@baloise/ds-tokens`) defines every `--ds-*`
  custom property and must load first — `ds-styles` no longer ships token values itself, only
  `var(--ds-*)` references. `design-system.css` (from `@baloise/ds-styles`) bundles the CSS reset,
  structural styles, and CSS-only component classes (`.ds-button`, `.ds-heading`, ...) — the only
  one you really need alongside tokens. `utilities.css` (spacing, layout, typography, color
  helpers, e.g. `.mt-base` used below) is entirely optional — drop it if you don't use utility
  classes. See **Development/Theming** for the ERV brand token files.
- **`<script type="module">` / `<script nomodule>`** — registers the web components (`<ds-root>`,
  `<ds-stage>`, etc.) used in markup. The `nomodule` variant is a fallback for browsers without
  ES module support.
- **`<ds-root>`** — the root layout web component; wrap your page content in it.
- **`<h1 class="ds-heading">` / `<button class="ds-button">`** — plain HTML styled with a CSS
  class. No script needed for these — only elements that need JS behavior (like `<ds-root>`) are
  web components.

### CDN

Prototyping or don't want to install anything? Load everything straight from
[jsDelivr](https://www.jsdelivr.com/), a CDN, by adding these to `<head></head>`:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@baloise/ds-tokens/css/base" />
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@baloise/ds-styles/css/design-system" />
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@baloise/ds-styles/css/utilities" />
<script
  type="module"
  src="https://cdn.jsdelivr.net/npm/@baloise/ds-core/dist/design-system/design-system.esm.js"
></script>
<script
  nomodule
  src="https://cdn.jsdelivr.net/npm/@baloise/ds-core/dist/design-system/design-system.js"
></script>
```

Same as before, only `base.tokens.css` and `design-system.css` are really required — drop
`utilities.css` if you don't use utility classes. The rest of the page (the
`<meta name="design-system-config">` tag, `<ds-root>`, etc.) works exactly like the "Plain HTML"
example above — only where the CSS/JS come from changes.

**TIP**

Not recommended for production — it depends on a third party to host and distribute the assets.
Pin a specific version rather than relying on the latest one:
`https://cdn.jsdelivr.net/npm/@baloise/ds-styles@16/css`

</InfoQuote>

## Installation

If you do not have a React app yet, create one with [Vite](https://vite.dev/guide/) (recommended for SPAs) or [Next.js](https://nextjs.org/docs/app/getting-started).

<InfoQuote>
  **Recommendations**

  - Use **TypeScript**. `@baloise/ds-react` ships its own types; no extra `@types` package or `tsconfig` flags are
    needed.
  - Use **SCSS** as stylesheet format to access breakpoint mixins and more. A pre-built CSS bundle is also available.
  - `react` and `react-dom` **18** or **19** are required as peer dependencies.
</InfoQuote>

Install the React bindings and the global styles. All three packages are required.

```bash
npm add -E @baloise/ds-react @baloise/ds-styles @baloise/ds-tokens
// or
pnpm add -E @baloise/ds-react @baloise/ds-styles @baloise/ds-tokens
```

## Usage

Component styles are automatically loaded lazily in the browser. Global CSS (design tokens, fonts, resets, utilities) needs to be imported into the application.

`@baloise/ds-styles` no longer ships design tokens itself — only `var(--ds-*)` references — so
`@baloise/ds-tokens` must be imported too, before `@baloise/ds-styles`:

```typescript
import '@baloise/ds-tokens/css/base'
import '@baloise/ds-styles/css/design-system'
```

`@baloise/ds-styles/css/design-system` bundles reset, structural styles, and CSS-only component classes
(`.ds-button`, `.ds-heading`, ...) together. Utility classes (spacing, layout, typography, color
helpers, ...) are a separate, optional import:

```typescript
import '@baloise/ds-tokens/css/base'
import '@baloise/ds-styles/css/design-system'
import '@baloise/ds-styles/css/utilities'
```

<InfoQuote>
Using a different brand? Import `@baloise/ds-tokens/css/erv`
instead of `@baloise/ds-tokens/css/base` — each is a complete, standalone token set. See
**Development/Theming**.
</InfoQuote>

### DsRootProvider

Wrap the application in `DsRootProvider`. It is the React root for Design System config: it initializes the system once and renders `DsRoot` so nested components pick up brand, region, language, and animation settings.

Pass live config as props. If you omit them, components still work with the default config. Region and language can also be changed at runtime — update the props from React state. See **Development/Internationalization**.

Do not call `initializeDesignSystem()` / `bootstrapDesignSystem()` in the React entry. `DsRootProvider` replaces that.

**main.tsx**

```tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'

import App from './App'

import '@baloise/ds-tokens/css/base'
import '@baloise/ds-styles/css/design-system'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

**App.tsx**

```tsx
import { DsRootProvider, DsAppFooter, DsButton, DsHeading } from '@baloise/ds-react'

function App() {
  return (
    <DsRootProvider
      className="has-sticky-footer"
      region="CH"
      language="de"
      allowedLanguages={['de', 'fr', 'it', 'en']}
    >
      <header>
        {/* Header content */}
      </header>
      <main className="ds-container">
        {/* Your application content */}
        <DsHeading>
          Hello World!
        </DsHeading>
        <DsButton>
          Button
        </DsButton>
      </main>
      <DsAppFooter>
        {/* Footer content */}
      </DsAppFooter>
    </DsRootProvider>
  )
}

export default App
```

## Frameworks

### Vite

Vite is the recommended setup for a client-side React SPA. Scaffold a TypeScript app, then install the Design System as described above. The app entry is `src/main.tsx`.

```bash
npm create vite@latest my-app -- --template react-ts
```

### Next.js

`@baloise/ds-react` is client-only today. Import Design System components from files marked `'use client'`. Wrap the tree in `DsRootProvider`.

### TypeScript

`@baloise/ds-react` publishes TypeScript declarations (`types` in `package.json` points at `dist/index.d.ts`). After installing the package, component props, events, and the `DsRootProvider` config are typed — no extra `@types/*` package or `tsconfig.json` changes are required.

Event handlers use the `onDs*` prefix (for example `onDsClick`) and receive the custom event, not a React synthetic event.
