<Banner label="Configuration" section="Development" />

<Lead>
  The Design System keeps one global configuration object per page. Every component reads from it to know which
  brand, region, and language to render, and reacts automatically when it changes.
</Lead>

## Config items

<Markdown>
  {`
| Key                | Type                 | Default                              | Description                                                                 |
| ------------------ | -------------------- | ------------------------------------- | ---------------------------------------------------------------------------- |
| \`brand\`          | \`DsBrand\`          | \`'helvetia'\`                        | Active brand theme (\`'baloise'\` \\| \`'helvetia'\`).                       |
| \`region\`         | \`DsRegion\`         | \`'CH'\`                              | Active region, drives number/date formats and legal content.                 |
| \`language\`       | \`DsLanguage\`       | \`'de'\`                              | Active interface language.                                                   |
| \`allowedLanguages\`| \`DsLanguage[]\`    | \`['de', 'fr', 'it', 'en']\`          | Languages offered in the language selector.                                  |
| \`fallbackLanguage\`| \`DsLanguage\`      | \`'de'\`                              | Used when \`language\` is not part of \`allowedLanguages\`.                  |
| \`animated\`       | \`boolean\`          | \`true\`                              | Disables all animation when \`false\` — useful for e2e tests.                |
| \`icons\`          | \`DsIcons\`          | Built-in icon set                     | Map of icon name → SVG markup, merged with the built-in set.                 |
| \`legalLinks\`     | \`DsLegalLinks\`     | Baloise/Helvetia legal links          | Footer legal links, keyed by region then language.                           |
| \`legalText\`      | \`DsLegalText\`      | Baloise/Helvetia copyright text       | Footer legal text, keyed by region then language.                            |
| \`socialLinks\`    | \`DsSocialLinks\`    | Baloise/Helvetia social links         | Footer social links, keyed by region.                                        |
| \`logger\`         | \`DsLogger\`         | all \`false\`, no components          | Enables component render/lifecycle/event logging for debugging.              |
`}
</Markdown>

<InfoQuote>
  `region` and `language` also determine which regions/languages are valid together — see
  [Internationalization](?path=/docs/development-internationalization--internationalization) for the full region/language matrix.
</InfoQuote>

<InfoQuote>
  `legalLinks`, `legalText`, and `socialLinks` are consumed by `ds-app-footer` — see its
  [Usage](?path=/docs/components-appfooter-usage--usage) page for the exact shape of each and how to
  override `legalText` per instance.
</InfoQuote>

## Set the initial configuration

<AngularFramework>

Pass the config to `provideDesignSystem()` in `app.config.ts`.

<Code language="typescript" code={`
import { ApplicationConfig } from '@angular/core'
import { provideDesignSystem } from '@baloise/ds-angular'

export const appConfig: ApplicationConfig = {
${' '}providers: [
${' '}${' '}provideDesignSystem({
${' '}${' '}${' '}defaults: {
${' '}${' '}${' '}${' '}brand: 'helvetia',
${' '}${' '}${' '}${' '}region: 'CH',
${' '}${' '}${' '}${' '}language: 'de',
${' '}${' '}${' '}${' '}allowedLanguages: ['de', 'fr', 'it', 'en'],
${' '}${' '}${' '}},
${' '}${' '}}),
${' '}],
}
`} />

</AngularFramework>

<ReactFramework>

Wrap the application in `DsRootProvider` and pass config items as props. It calls `initializeDesignSystem()` for you
on first render.

<Code language="tsx" code={`
import { DsRootProvider } from '@baloise/ds-react'

function App() {
${' '}return (
${' '}${' '}<DsRootProvider brand="helvetia" region="CH" language="de" allowedLanguages={['de', 'fr', 'it', 'en']}>
${' '}${' '}${' '}{/* Your application */}
${' '}${' '}</DsRootProvider>
${' '})
}
`} />

</ReactFramework>

<HTMLFramework>

Call `initialize()` before any design system component renders.

<Code language="ts" code={`
import { initialize } from '@baloise/ds-core'

initialize({
${' '}brand: 'helvetia',
${' '}region: 'CH',
${' '}language: 'de',
${' '}allowedLanguages: ['de', 'fr', 'it', 'en'],
})
`} />

For markup-only setups (CMS templates, server-rendered pages) where calling `initialize` isn't practical, a subset
of the config can instead be declared on a `<meta name="design-system-config">` tag in `<head>`:

<Code language="html" code={`
<meta
${' '}name="design-system-config"
${' '}data-brand="helvetia"
${' '}data-region="CH"
${' '}data-language="de"
${' '}data-allowed-languages="de,fr,it,en"
/>
`} />

Only `brand`, `region`, `language`, `fallbackLanguage`, `allowedLanguages` (comma-separated), and `animated`
(`"false"` or anything else, treated as a boolean) are read from the tag — everything else is JS-only config.

<InfoQuote>
  Precedence, lowest to highest: default config → `<meta>` tag → the config passed to `initialize` or
  `DsRootProvider`, which always wins.
</InfoQuote>

</HTMLFramework>

## Change configuration at runtime

<AngularFramework>

Import the `updateDs*` functions from `@baloise/ds-core` and call them wherever the change originates.

<Code language="typescript" code={`
import { Component } from '@angular/core'
import { updateDsLanguage, updateDsRegion, DsSwissLanguage } from '@baloise/ds-core'

@Component({
${' '}selector: 'app-tab-a',
${' '}templateUrl: './app-tab-a.html',
})
export class AppTabA {
${' '}changeLang(lang: DsSwissLanguage) {
${' '}${' '}updateDsLanguage(lang)
${' '}}

${' '}changeRegion() {
${' '}${' '}updateDsRegion('DE')
${' '}}
}
`} />

</AngularFramework>

<ReactFramework>

Update the props on `DsRootProvider` from React state — `brand`, `region`, `language`, `allowedLanguages`,
`fallbackLanguage`, and `animated` are kept in sync on every render. Nested design system components pick up the
new values automatically.

<Code language="tsx" code={`
import { useState } from 'react'
import { DsRootProvider } from '@baloise/ds-react'
import type { DsLanguage } from '@baloise/ds-core'

function App() {
${' '}const [language, setLanguage] = useState<DsLanguage>('de')

${' '}return (
${' '}${' '}<DsRootProvider region="CH" language={language} allowedLanguages={['de', 'fr', 'it', 'en']}>
${' '}${' '}${' '}<button onClick={() => setLanguage('fr')}>Français</button>
${' '}${' '}</DsRootProvider>
${' '})
}
`} />

<InfoQuote>
  `icons`, `legalLinks`, `legalText`, and `socialLinks` have no matching prop on `<ds-root>` — pass them once as
  props on `DsRootProvider` and it merges them into the config for you on every render, so updating them from
  state works the same way.
</InfoQuote>

</ReactFramework>

<HTMLFramework>

Call the matching `updateDs*` function from `@baloise/ds-core`, or set the property/attribute directly on
`<ds-root>` — both end up updating the same global config.

<Code language="typescript" code={`
import { updateDsLanguage, updateDsRegion, updateDsAllowedLanguages } from '@baloise/ds-core'

updateDsLanguage('de')
updateDsRegion('CH')
updateDsAllowedLanguages(['fr', 'it'])
`} />

<Code language="html" code={`
<ds-root id="root" region="CH" language="de"></ds-root>

<script>
${' '}document.querySelector('#root').language = 'fr'
</script>
`} />

</HTMLFramework>

## Listen for changes

Only `brand`, `region`, `language`, `allowedLanguages`, `fallbackLanguage`, and `animated` fire a dedicated change
event. Everything else (`icons`, `legalLinks`, `legalText`, `socialLinks`, `logger`) requires the full-state
`onDsConfigChange` callback.

<AngularFramework>

<Code language="typescript" code={`
import { Component, OnInit } from '@angular/core'
import { onDsConfigChange, DsConfigState } from '@baloise/ds-core'

@Component({
${' '}selector: 'app-sample',
${' '}templateUrl: './sample.html',
})
export class Sample implements OnInit {
${' '}constructor(private yourLangService: YourLangService) {}

${' '}ngOnInit(): void {
${' '}${' '}// IMPORTANT: register your config update callback in ngOnInit instead of the constructor
${' '}${' '}onDsConfigChange((config: DsConfigState) => {
${' '}${' '}${' '}this.yourLangService.changeLanguage(config.language)
${' '}${' '}})
${' '}}
}
`} />

</AngularFramework>

<ReactFramework>

Listen to the corresponding `onDs*Change` event on `DsRootProvider` instead of calling `onDsConfigChange` directly.

<Code language="tsx" code={`
import { useState } from 'react'
import { DsRootProvider } from '@baloise/ds-react'
import type { DsLanguage } from '@baloise/ds-core'

function App() {
${' '}const [language, setLanguage] = useState<DsLanguage>()

${' '}return (
${' '}${' '}<DsRootProvider
${' '}${' '}${' '}region="CH"
${' '}${' '}${' '}language="de"
${' '}${' '}${' '}onDsLanguageChange={event => setLanguage(event.detail)}
${' '}${' '}${' '}onDsRegionChange={event => console.log('region changed to', event.detail)}
${' '}${' '}>
${' '}${' '}${' '}{/* Your application */}
${' '}${' '}</DsRootProvider>
${' '})
}
`} />

For `icons`, `legalLinks`, `legalText`, `socialLinks`, or `logger`, fall back to `onDsConfigChange`.

<Code language="tsx" code={`
import { onDsConfigChange, DsConfigState } from '@baloise/ds-core'

onDsConfigChange((config: DsConfigState) => {
${' '}// do something with the updated config here
})
`} />

</ReactFramework>

<HTMLFramework>

Register a callback with `onDsConfigChange`, or listen to the matching DOM event on `<ds-root>` if you only care
about one field.

<Code language="typescript" code={`
import { onDsConfigChange, DsConfigState } from '@baloise/ds-core'

onDsConfigChange((config: DsConfigState) => {
${' '}// do something with the updated config here
})
`} />

<Code language="html" code={`
<ds-root id="root"></ds-root>

<script>
${' '}document.querySelector('#root').addEventListener('dsLanguageChange', event => {
${' '}${' '}console.log('language changed to', event.detail)
${' '}})
</script>
`} />

</HTMLFramework>
