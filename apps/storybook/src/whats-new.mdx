## A New Architecture for Multi-Brand at Scale

Under the hood, the design system moved to an architecture built to support many brands and themes without
duplicating work:

- **Tokens defined once, synced everywhere** — design tokens are now defined once and synced automatically across
  every platform — web, iOS, Android, and Figma — so a change to a token propagates everywhere it's consumed
  instead of being re-implemented per platform.
- **More detailed, Figma-aligned tokens** — token definitions are more detailed and stay in sync with Figma.
- **TOKY, our token editor** — a new Theme Editor lets you define a new brand or theme and see the result with a
  live preview, without touching code or waiting on a build.
- **Multi-brand by design** — the system is built for multi-brand theming from the ground up, making it easier to
  support white-label applications and partner brands alongside Helvetia.

## A More Robust Foundation for Every Component

Besides multi-brand support, we also rebuilt how components are constructed — making pages load faster, look more
consistent, and work in more places, without anyone having to change how they use the design system:

### 🫧 Style isolation with Shadow DOM

every component now keeps its own styling sealed off from the rest of the
page. In practice, that means a component always looks exactly as designed, no matter what other styles exist on
the site it's placed on, and it drops cleanly into Angular, React, or any other setup without clashing.

### 🚀 Faster first paint with SSR support

Pages built with Next.js can now render components on the server before sending them to the browser. Visitors see a finished page sooner instead of watching it build
itself, and search engines can read the page content more easily too.

No framework required — a single function renders components to real HTML on the server, ready to send straight
to the browser. See the full walkthrough in the
[Server-Side Rendering guide](/docs/development-getting-started--docs#server-side-rendering-ssr).

<Code
  language="js"
  noPreview
  code={`
import { renderToString } from '@helvetia-design/core/hydrate'

const fragment = \`
<ds-root>
  <ds-button>Button</ds-button>
</ds-root>
\`

const { html } = await renderToString(fragment)

res.type('html').send(html)
`}
/>

### ⚡ More components that are just HTML and CSS

Growing number of components no longer need JavaScript to work at all. Pages using them load faster and feel snappier for visitors, since there's simply less code for the browser to run.

<Code
  language="html"
  code={`
<ds-button color="primary">Web-component</ds-button>
<button class="ds-button is-primary">CSS-only</button>
`}
/>

### And More…

Alongside the architecture work, a few other pieces landed:

- ♿ **Accessibility** — components have been updated to better meet WCAG 2.2 AA success criteria, keeping
  applications compliant and inclusive by default.
- 🛡️ **Cyber Resilience Act** — the design system now generates a Software Bill of Materials, runs automated
  dependency scanning via Dependabot, and follows a documented security policy — aligning with the EU Cyber
  Resilience Act.
- 🤖 **AI Context Foundation** — every package now ships a CONTEXT.md documenting its purpose, structure, and
  conventions, laying the groundwork for AI agent skills to come.
- ⚛️ **React Integration** — new hooks — _**useModal**_, _**useToast**_, _**useSnackbar**_ — and a
  _**DsRootProvider**_ replace the old _**bootstrapDesignSystem**_ setup, giving React apps simpler, centralized
  configuration.
- 📚 **Improved Documentation** — a theme switcher and a web component preview switcher let you compare themes
  and components side by side, alongside usage guides and live code examples with CodePen.

## What's Next (Roadmap)

Here's what we're working on next:

- 🚚 **Prepage migration from Baloise to Helvetia** — moving remaining Baloise-branded pages and apps onto the
  Helvetia Design System, using our own AI agent skill set to migrate `bal-` components to their `ds-` equivalents
  faster and more consistently.
- 🧩 **Missing components from Helvetia apps** — filling the gaps by adding components that Helvetia apps still
  rely on outside the design system.
- 🎨 **Better Figma support** — creating components in Figma that are built directly from our design tokens.
- 🧱 **Blocks and page templates** — pre-assembled sections and full page templates on top of our components.
- ✨ **And more** — the roadmap keeps growing as we learn from you.
