# Plan: Restyle changelog with emoji headers, deps section, and contributor thank-you list

**Milestone:** 🚀 Release Helvetia Design System v0.0
**Ticket:** [#2290](https://github.com/baloise/design-system/issues/2290)

## Context

The changelog currently groups release notes purely by semver bump level
(`### Major Changes` / `### Minor Changes` / `### Patch Changes`), generated by
`.changeset/my-changelog-config.js` (a custom `@changesets/changelog-github`-style
config) plus `@changesets/apply-release-plan`. The goal is the same visual polish
as MDX's changelog example — emoji category headers, a dedicated dependency-updates
section, a "Thank You" contributor list — but using our own emoji set from
`.github/issue-branch.yml` where practical, keeping bump-level grouping (not
MDX's full type-based classification), and without touching the changeset-authoring
flow.

Key finding from investigation: the `### {Major,Minor,Patch} Changes` headers are
hardcoded inside `@changesets/apply-release-plan` (a dependency) —
`getChangelogEntry` builds them as `capitalize(type) + ' Changes'` directly. There
is no supported hook in `my-changelog-config.js` to rename them, and no built-in
"Thank You"/contributor feature anywhere in `@changesets/*`. Both must be done as a
post-processing pass over `CHANGELOG.md` immediately after `changeset version` runs.

Confirmed decisions:

- Keep grouping by bump level (no full type-based reclassification).
- Header renames: `### Major Changes` → `### 💥 Breaking Change`,
  `### Minor Changes` → `### ✨ Features`, `### Patch Changes` → `### 🩹 Fixes`
  (🩹 intentionally copied from the MDX example, not from our own emoji set).
- Split `- **deps**: ...` bullets out of Fixes into their own
  `### 🧱 Updated Dependencies` section — deps changesets (e.g. Renovate-authored)
  are already scoped `deps` and bumped `patch` (confirmed via existing
  `.changeset/*.md` files and prior `CHANGELOG.md` history, e.g.
  `- **deps**: Update stencil to 4.11.0 (...)`).
- Add a `### ❤️ Thank You` section listing unique contributors as
  `- [@user](https://github.com/user)`.
- `scripts/create-changeset.mjs` needs **no changes** — existing scope + bump-level
  prompts already carry enough information to place each entry.
- Section order within a version block: Breaking Change, Features, Fixes,
  Updated Dependencies, Thank You (only sections with content are emitted).

## Explicitly out of scope

- Type-based (feature/fix/chore/refactor/perf) classification independent of bump
  level — rejected in favor of keeping bump-level grouping.
- Any change to `scripts/create-changeset.mjs` prompts.
- Patching `@changesets/apply-release-plan` via `pnpm patch` — rejected in favor of
  a post-processing script, to avoid fragility across dependency upgrades.
- Per-package changelogs — this repo only has a single root `CHANGELOG.md`.

## Implementation

### 1. `.changeset/my-changelog-config.js`

In `getReleaseLine`, after resolving `links` (which already includes `links.user`
via `getGithubInfo.getInfo` / `getInfoFromPullRequest`), append a hidden marker to
the returned bullet when a user is present:

```js
const authorMarker = links.user
  ? `<!-- author:${links.user.match(/\[@?([^\]]+)\]/)?.[1] ?? ''} -->`
  : ''
```

(`links.user` from `@changesets/get-github-info` is already a markdown link like
`[@username](https://github.com/username)` — extract the username, don't dump the
raw markdown into the comment.)

Append `authorMarker` to the end of the returned template string, so a rendered
bullet looks like:

```
- **deps**: update angular to 22.1.2 ( [#123](...))<!-- author:srvGitLabRenovate -->
```

Leave `getDependencyReleaseLine` as-is (returns `''`) — deps-scoped changes already
flow through the normal `getReleaseLine` path per the confirmed `CHANGELOG.md`
evidence.

### 2. New `scripts/format-changelog.mjs`

A standalone Node script (same style as `scripts/create-changeset.mjs` /
`scripts/sync-codepen-version.mjs` — plain ESM, no deps beyond `node:fs`).
Responsibilities:

1. Read root `CHANGELOG.md`.
2. Isolate the **first** version block (from the first `## x.y.z` heading to the
   next `## ` heading or EOF) — this is the block `changeset version` just wrote.
3. Within that block:
   - Rename `### Major Changes` → `### 💥 Breaking Change`,
     `### Minor Changes` → `### ✨ Features`,
     `### Patch Changes` → `### 🩹 Fixes` (simple string replacement,
     order-independent).
   - Extract every bullet under `### 🩹 Fixes` (or wherever it landed) whose text
     starts with `- **deps**:` (after trimming), remove it from Fixes, and collect
     it into a new `### 🧱 Updated Dependencies` list. If Fixes becomes empty, drop
     the empty heading.
   - Scan the whole block for `<!-- author:NAME -->` markers, collect into a
     `Set` (skip empty), strip the markers from all bullet text (visible output
     should have no leftover HTML comments), and if any authors were found, append
     `### ❤️ Thank You` with one `- [@name](https://github.com/name)` line per
     unique author, sorted alphabetically for stable diffs.
   - Reassemble sections in the fixed order: Breaking Change, Features, Fixes,
     Updated Dependencies, Thank You (only emit headings that have content).
4. Splice the rewritten block back into the full file content and write it back
   with `writeFile`.

Keep it dependency-free and defensive (no crash if a section is missing —
changesets already omits headings with zero entries).

### 3. `package.json`

Update the existing chained script:

```json
"changeset:version": "changeset version && node scripts/format-changelog.mjs && node scripts/sync-codepen-version.mjs && pnpm install --no-frozen-lockfile --lockfile-only"
```

(insert the new formatting step right after `changeset version`, before the
codepen sync).

## Definition of done

- [ ] `.changeset/my-changelog-config.js` emits a hidden author marker per bullet
      when a GitHub user can be resolved, without changing the visible bullet
      text/format.
- [ ] `scripts/format-changelog.mjs` rewrites only the freshly-generated top
      version block of `CHANGELOG.md`: renames the three bump-level headers to
      their emoji equivalents, moves `**deps**:` bullets out of Fixes into a new
      Updated Dependencies section, and appends a deduped, alphabetized Thank You
      section built from the author markers (which are stripped from the final
      output).
- [ ] `package.json`'s `changeset:version` script runs the new formatting step
      right after `changeset version` and before the codepen/lockfile sync steps.
- [ ] Verified end-to-end with throwaway changesets (patch/minor/deps-scoped) run
      through `changeset version` + the formatter, confirming correct headers,
      correct deps split, no leftover HTML comments, and correct Thank You output
      — then the test changesets/version bump are reverted so only the real source
      changes remain.
- [ ] Changeset entry for the tooling change itself (scope `devkit`, per
      `scripts/create-changeset.mjs`'s `SCOPE_PACKAGE_MAP`), if the repo's
      convention requires one for tooling-only changes.
