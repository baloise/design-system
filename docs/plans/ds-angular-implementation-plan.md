# Implementation Plan: `ds-angular` package

Status: ready for implementation. Nothing in this plan has been implemented or committed yet.

Related decisions: [ADR-0006](../adr/0006-ds-angular-uses-stock-output-target.md)
(no custom `libs/output-target-angular` lib), [ADR-0004](../adr/0004-react-smoke-test-app-outside-workspace.md)
(smoke-test app lives outside the workspace — same pattern reused here for Angular).

## Scope

Add Angular bindings for the Stencil component library, generated by
`@stencil/angular-output-target`, published as `@baloise/ds-angular`,
verified in CI by scaffolding a real (outside-workspace) Angular CLI app
and running Playwright against it, plus a one-command local script to
scaffold that same app for manual poking. Angular 22 only.

Explicitly out of scope for this pass: form components' `ControlValueAccessor`
integration (`ValueAccessorConfig`s, reactive-forms wiring), any Angular
version older than 22, SSR/hydrate support, reusing
`packages/playwright`'s component-mount fixtures, and any services/directives
from the old pre-shadow-DOM `packages/angular` (config service, modal/toast/
snackbar overlay services, focus directive, breakpoints service, etc.) — this
MVP is component bindings only.

## Steps

### 1. Remove the dormant custom output-target lib

- [ ] Delete `libs/output-target-angular/` entirely (package, generator
      code, control-value-accessor resources, tests).
- [ ] Remove `libs-output-target-angular` from `pnpm-workspace.yaml`
      packages resolution if referenced explicitly, and from any
      `package.json` dependency lists (check `packages/core/package.json`
      for a workspace dependency, even though it's currently unused via
      the commented-out import).

### 2. Stencil output target (`packages/core`)

- [ ] Add `@stencil/angular-output-target` as a dev dependency of
      `packages/core`.
- [ ] Rewrite `packages/core/config/stencil.bindings.angular.ts`:
  ```ts
  import { angularOutputTarget } from '@stencil/angular-output-target'

  export const AngularGenerator = (): any =>
    angularOutputTarget({
      componentCorePackage: '@baloise/ds-core',
      outputType: 'standalone',
      customElementsDir: 'components',
      directivesProxyFile: '../angular/src/generated/proxies.ts',
      directivesArrayFile: '../angular/src/generated/proxies-list.ts',
    })
  ```
  (mirrors `stencil.bindings.react.ts`'s shape; confirm exact option names
  against the installed `@stencil/angular-output-target` version once
  added — the API may differ slightly from the deleted custom lib's
  `OutputTargetAngular` type.)
- [ ] In `stencil.config.ts`, replace the commented-out
      `// import { AngularGenerator } ...` with a live import, and add
      `!IS_DS_DEVELOPMENT && !IS_DS_DOCUMENTATION && AngularGenerator()` to
      `outputTargets`, in the same guarded style as `ReactGenerator()`.
- [ ] `pnpm build` (core) and confirm `packages/angular/src/generated/*` is
      produced, and that each generated component self-registers its
      custom element (via `customElementsDir`) rather than requiring a
      separate `defineCustomElements()` call.

### 3. New package `packages/angular` (`@baloise/ds-angular`)

- [ ] `package.json`:
  - `name: "@baloise/ds-angular"`, version matching current DS versioning.
  - `peerDependencies`: `@angular/core: ">=22.0.0"`,
    `@angular/common: ">=22.0.0"`. No `@angular/forms`, no `rxjs` (not
    needed without `ValueAccessor`/forms integration).
  - `dependencies`: `@baloise/ds-core`.
  - `devDependencies`: `ng-packagr` (version matching Angular 22),
    `@angular/core`, `@angular/common`, `@angular/compiler-cli` (or
    whatever `ng-packagr` requires as peers for the build step).
  - `scripts.build`: `ng-packagr -p ng-package.json` (matches the old
    pre-shadow-DOM `packages/angular` convention, not the plain-`tsc`
    convention used by `packages/react`/`packages/tokens` — see
    ADR-0006's build-tooling rationale: proper Angular Package Format
    output for AOT-compiling consumers).
  - `files: ["dist/"]`, `sideEffects: false`.
- [ ] `ng-package.json`:
  ```json
  {
    "$schema": "../../node_modules/ng-packagr/ng-package.schema.json",
    "dest": "dist",
    "lib": { "entryFile": "src/index.ts" },
    "allowedNonPeerDependencies": ["@baloise/ds-core"]
  }
  ```
- [ ] `tsconfig.json` / `tsconfig.lib.json` per repo convention, adjusted
      for Angular's decorator/module requirements (`experimentalDecorators`,
      `useDefineForClassFields: false` if needed by the Angular version).
- [ ] `src/index.ts`:
  ```ts
  import { DsConfig, initializeDesignSystem } from '@baloise/ds-core'

  interface DsAngularConfig {
    defaults?: DsConfig
  }

  export const bootstrapDesignSystem = (config: DsAngularConfig = {}) => {
    initializeDesignSystem({
      ...config.defaults,
      httpFormSubmit: false,
    })
  }

  export * from './generated/proxies'
  ```
  (mirrors `packages/react/src/index.ts` exactly — confirm the generated
  file's actual export name/path once step 2 produces it; may be
  `./generated/proxies` or a re-exported index depending on
  `@stencil/angular-output-target`'s output shape.)
- [ ] `eslint.config.js` per repo convention (plain repo eslint config,
      no `@angular-eslint` plugin needed — this package's only
      hand-authored file is a trivial bootstrap function, not a
      component/template needing Angular-specific lint rules).
- [ ] `packages/angular/CONTEXT.md` documenting the package (purpose, that
      it's a thin generated-bindings layer, pointer to ADR-0006, explicit
      note that form components have no `ControlValueAccessor` support
      yet).
- [ ] Add a row for the new context in root `CONTEXT-MAP.md`.
- [ ] Update `libs/CONTEXT.md` to remove the `output-target-angular`
      section (now deleted) from "Output Targets in This System".
- [ ] `pnpm changeset` entry for the new package.

### 4. Framework smoke-test app template (`test/angular/base`)

- [ ] `test/angular/base/app/`: real Angular CLI scaffold
      (`ng new ds-angular-smoke --standalone --routing=false --style=scss
      --skip-git`), exercising a representative set of components,
      including at least one form component (rendered as a raw wrapper,
      no reactive-forms binding, consistent with this MVP's scope).
- [ ] `test/angular/base/app/playwright.config.ts` + `e2e/*.spec.ts`:
      standalone Playwright config (not `packages/playwright`'s
      fixtures) — specs covering: app renders, a component emits an event
      on interaction (e.g. button click / input change), no console
      errors on load.
- [ ] `test/angular/base/v22/package.json`: version overlay pinning
      `@angular/core`/`@angular/common`/`@angular/cli` to v22, plus
      `@playwright/test` devDependency, `scripts.link` (pnpm link step),
      `scripts.copy` (copies `packages/angular/dist` into the generated
      app's `node_modules` shape, mirroring `test/react`'s overlay
      convention).
- [ ] `test/angular/build.sh`: clean + copy `base/app` + version overlay
      into `test/angular/v22/`, then build `@baloise/ds-core` and
      `@baloise/ds-angular`, then `pnpm link` them into the generated app
      (per ADR-0004's pattern) — not a pnpm workspace member.
- [ ] `test/angular/start.sh`: starts the generated app's dev server
      (`ng serve` via `@angular/build`).
- [ ] Ensure `test/angular/` (except `base/`) is gitignored — it's
      generated output.

### 5. Root convenience script

- [ ] Add `angular:app` to root `package.json`:
      `"angular:app": "bash test/angular/build.sh v22 && bash
      test/angular/start.sh v22"`, alongside `react:app`, `pnpm start`,
      `pnpm docs`.

### 6. CI (`.github/workflows/continuous.yml`)

- [ ] Add an `angular:` job, mirroring the existing `react:` job:
  - `needs: [assembleInformation]`
  - `strategy.matrix.apps: [v22]` (single entry, structured so a second
    version overlay + matrix entry is a copy-paste addition later)
  - Steps: checkout → `./.github/workflows/actions/setup-environment` →
    `pnpm install --frozen-lockfile` → `pnpm exec turbo run build
    --filter=@baloise/ds-core --filter=@baloise/ds-angular` → `bash
    test/angular/build.sh ${{ matrix.apps }}` → `pnpm exec playwright
    install --with-deps chromium` (in the generated app dir) → run the
    generated app's Playwright tests → upload the HTML report as an
    artifact on failure (same pattern as the `react:` job).

### 7. Docs / cleanup

- [ ] Update `TODOS.md`: mark a new "Angular bindings" row ✅ (component
      wrappers, this MVP's scope), and add a new "Angular forms
      integration" row ⬜ for the deferred `ControlValueAccessor` work,
      replacing the single "Anuglar 2.0" row.
- [ ] Confirm `README.md` / `docs/` mention `@baloise/ds-angular` alongside
      the other published packages once it's ready to publish.

  deleted custom lib's API, before copying the config snippet in step 2

  `src/index.ts` re-export right.
- Whether `ng-packagr`'s required peer/dev tooling (e.g.
  `@angular/compiler-cli`) pulls in versions that conflict with anything
  else in the root `pnpm-workspace.yaml` catalog — check during `pnpm
  install` in step 3.
- Root script name `angular:app` — verify no collision with an existing
  script name at implementation time (none found during planning).
