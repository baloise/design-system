# 6. `ds-angular` uses the official `@stencil/angular-output-target`, retiring the custom `libs/output-target-angular`

Date: 2026-07-28

## Status

Accepted

## Context

`libs/output-target-angular` is a hand-rolled reimplementation of Angular
proxy/directive generation, not a wrapper around any official Stencil
package. It was built to support `ValueAccessorConfig`s wiring form
components (`ds-select`, `ds-checkbox`, `ds-date`, …) into Angular's
`ControlValueAccessor`/reactive-forms machinery — logic the stock
`@stencil/angular-output-target` ecosystem doesn't provide out of the box.
It is currently dormant: `packages/core/config/stencil.bindings.angular.ts`
still configures it, but the import is commented out in
`stencil.config.ts`, and `packages/angular` doesn't exist on this branch.

[ADR-0003](0003-ds-react-no-custom-output-target.md) already established
that React needed no equivalent custom layer, because
`@stencil/react-output-target` generates typed wrappers directly and React
consumers handle controlled/uncontrolled state themselves.

For this Angular MVP, form components and `ControlValueAccessor` wiring are
explicitly out of scope (see
`docs/plans/ds-angular-implementation-plan.md`). Without that requirement,
the only reason `libs/output-target-angular` existed no longer applies:
the stock `@stencil/angular-output-target` package generates the same
shape of proxy/standalone components without it.

## Decision

`ds-angular` bindings are generated by calling `angularOutputTarget()`
from the official `@stencil/angular-output-target` package directly,
inside `packages/core/config/stencil.bindings.angular.ts` (rewritten, not
just re-enabled), registered in `stencil.config.ts`'s `outputTargets`. The
`outputType` is `'standalone'` — no `NgModule` is generated, matching the
"newest Angular version only" constraint. No `valueAccessorConfigs` are
configured and no components are excluded — every `ds-*` component
(including form components) gets a plain Angular wrapper with inputs,
outputs, and methods, but no reactive-forms integration.

`libs/output-target-angular` is deleted, not just left dormant. Its
`ValueAccessorConfig` logic is not lost conceptually — it's deferred, and
tracked as a separate, explicit follow-up (see `TODOS.md`), not silently
dropped.

## Consequences

- Parity with React's binding strategy: both frameworks now use their
  respective off-the-shelf Stencil output targets, with no custom
  generator code to own or test.
- Angular consumers using `ds-select`, `ds-checkbox`, `ds-date`, etc.
  inside Angular reactive/template-driven forms get raw component
  inputs/outputs/events, not `formControlName`/`ngModel` integration, until
  the deferred forms-integration follow-up ships. This is a real
  regression relative to the old (pre-shadow-DOM) `packages/angular`,
  which shipped full `ControlValueAccessor` support — but it's a
  deliberate, scoped-down MVP trade-off, not an oversight.
- If `ControlValueAccessor` support is added later, it will need its own
  design (likely a thin wrapper layer on top of the generated standalone
  components, since the stock output target still won't provide it) —
  this ADR does not rule that out, it just says today's MVP scope doesn't
  require it.
- Removes the only other precedent (besides `libs/output-target-web`) for
  "custom output-target logic" in `libs/`, making `libs/CONTEXT.md` in
  need of an update once this ships.
