# 27. Prefix CSS-only component classes with `ds-`

Package: `packages/core`, `packages/css`, `apps/storybook`

Date: 2026-09-07

## Status

Accepted

## Context

CSS-only mode lets consumers use design-system styling on plain HTML
(`<button class="button">`) without loading the web component JavaScript.
This mode styles generic, unprefixed class names — `.button`, `.card`,
`.badge`, and so on — matching the component's root element and its
structural sub-elements (`.card-header`, `.item-content`, etc.).

The design system is increasingly embedded inside CMS-authored pages. CMS
themes and page builders commonly define their own generic utility/component
classes using the exact same short, common words (`button`, `card`, `list`,
`field`, `title`, `text`, `close`, ...). When both stylesheets are loaded on
the same page, whichever cascades last wins, silently overriding the other's
styling — a collision that is invisible until a page renders wrong in
production and is expensive to root-cause because nothing in either
stylesheet looks broken in isolation.

This also completes a pattern the codebase had started but not finished:
`form.style.scss` already carried both `.field` and `.ds-field` selectors in
two places, evidently a partial migration toward prefixed classes that never
propagated to the other 34 selectors in that file, nor to any other
component.

Considered alternatives:

- **Dual-class transition** (ship `.button` and `.ds-button` together for a
  deprecation window, as `form.style.scss` had started to do). Rejected: it
  doubles every selector indefinitely until a second migration removes the
  old class, delays the actual collision fix, and the half-finished
  `.field`/`.ds-field` state already showed this doesn't reliably get
  finished later. CSS-only mode is opt-in per project, so there's no
  runtime auto-upgrade path that would make a transition window valuable —
  consumers update their markup as part of picking up the major version.
- **Scope only root classes**, leaving sub-elements (`.card-header`,
  `.item-content`) unprefixed. Rejected: sub-element classes
  are just as likely to collide with CMS class names (`.title`, `.content`,
  `.close`, `.text` are arguably more collision-prone than component roots),
  and partial coverage would leave the exact failure mode this ADR exists to
  prevent.
- **Namespace via a wrapper attribute or `[data-ds]` scoping selector**
  instead of renaming classes. Rejected: requires consumers to add a
  wrapper/attribute to every styled element rather than a mechanical
  find-and-replace on existing markup, and doesn't match how the rest of the
  design system is consumed (plain classes, no required host attribute).

## Decision

Every CSS-only component's root and structural sub-element class is renamed
to a `ds-`-prefixed form: `.button` → `.ds-button`, `.card-header` →
`.ds-card-header`, `.item-content` → `.ds-item-content`, etc. Modifier classes
(`.is-*`, `.has-*`), utility classes generated by the `packages/css` UnoCSS
preset (`.bg-*`, `.p-*`, ...), and CSS custom properties are unaffected —
only classes that name a component or one of its parts move.

This is a **single breaking change with no dual-class transition period**.
The curated old→new class map was built by hand from every
`*.style.scss` selector in `packages/core/src/components/**`, then applied
mechanically with `scripts/rename-component-classes.mjs` across component
SCSS, the `packages/core` shared shadow-DOM/mixin partials that style
slotted light-DOM content with the same class names (e.g. a host component's
`::slotted(.button)`), `packages/css`'s own structure reset, Storybook
stories, and Playwright visual fixtures. Already-`ds-`-prefixed classes,
`is-*`/`has-*` modifiers, and classes that aren't design-system-owned (e.g.
tag's `:not(.token)` guard, which excludes an unrelated third-party class)
were excluded from the map. This also completes the previously half-finished
`.field`/`.ds-field` synonym in `form.style.scss` — every `.field` selector
there is now `.ds-field`, with no dual-class leftover.

## Consequences

- CSS-only mode markup is a breaking change for existing consumers: every
  `class="button"` (and the sub-element equivalents) must become
  `class="ds-button"` when upgrading to this major version. There is no
  runtime shim — pages must update their markup.
- CSS-only class names now carry the same collision resistance as the
  `ds-*` custom element tag names, which was the actual goal: a CMS theme
  defining its own `.button`/`.card`/`.title` no longer silently wins or
  loses the cascade against the design system's CSS-only classes.
- `scripts/rename-component-classes.mjs` is kept in the repo as a record of
  the migration and the curated class map, not as a tool meant to run again
  — future components should be authored with the `ds-` prefix from the
  start rather than relying on a follow-up rename pass.
